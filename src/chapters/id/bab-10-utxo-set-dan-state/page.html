Bab 10 · 10.1
Bitcoin tidak menyimpan saldo — ia menyimpan output
Apa itu UTXO Set?

Bitcoin tidak menyimpan saldo. Ini salah satu hal yang paling sering disalahpahami oleh orang yang baru mengenal Bitcoin. Wallet kamu tidak punya "saldo 0.5 BTC" yang tersimpan di suatu tempat. Yang ada adalah kumpulan output transaksi yang belum dihabiskan, yang jika dijumlahkan, memberikan angka yang kita sebut saldo.

Rekap UTXO

Setiap transaksi Bitcoin mengonsumsi UTXO yang ada sebagai input dan menciptakan UTXO baru sebagai output. UTXO yang sudah dipakai tidak bisa dipakai lagi. UTXO yang baru dibuat menunggu untuk dipakai di transaksi berikutnya. UTXO set adalah kumpulan semua UTXO yang saat ini ada di seluruh jaringan Bitcoin, yaitu semua output yang sudah dibuat tapi belum dihabiskan. Ini adalah "state" Bitcoin saat ini.

Mengapa UTXO set penting?

UTXO set adalah sumber kebenaran tunggal tentang kepemilikan bitcoin. Setiap full node menyimpan salinan lengkap UTXO set dan memperbarui setiap kali ada block baru. Saat kamu mengirim transaksi, node memverifikasi bahwa UTXO yang kamu klaim sebagai input benar-benar ada di UTXO set dan belum dihabiskan. Ini adalah mekanisme yang mencegah double spend: kalau kamu mencoba menggunakan UTXO yang sama dua kali, node akan mendeteksi bahwa UTXO itu sudah tidak ada di UTXO set setelah transaksi pertama dikonfirmasi.

Ukuran UTXO set

UTXO set jauh lebih kecil dari blockchain penuh. Blockchain menyimpan seluruh sejarah semua transaksi sejak genesis block, yang per pertengahan 2026 sudah lebih dari 700 GB. UTXO set hanya menyimpan output yang belum dihabiskan, yang ukurannya sekitar 11 GB. Ini yang memungkinkan full node bisa memverifikasi transaksi baru dengan sangat cepat tanpa perlu membaca seluruh blockchain.

UTXO set dan memori

Full node menyimpan UTXO set di memori atau database yang dioptimalkan untuk akses cepat. Setiap kali block baru masuk, node menghapus UTXO yang dihabiskan dan menambahkan UTXO baru. Operasi ini harus sangat efisien karena terjadi setiap 10 menit.

UTXO set adalah salah satu desain paling elegan di Bitcoin. Dengan hanya menyimpan "apa yang ada sekarang" bukan "semua yang pernah terjadi", Bitcoin memungkinkan verifikasi transaksi yang cepat dan efisien tanpa harus membaca seluruh sejarah blockchain.

Bab 10 · 10.2
Setiap block mengubah state Bitcoin secara deterministik
Bagaimana UTXO Set Diperbarui

Setiap kali block baru ditambahkan ke blockchain, UTXO set harus diperbarui. Ini adalah operasi yang terjadi ribuan kali sehari di setiap full node di seluruh jaringan, dan harus berjalan dengan sangat efisien.

Dua operasi dasar

Ada dua operasi yang terjadi saat UTXO set diperbarui: penghapusan dan penambahan. Setiap transaksi dalam block mengonsumsi beberapa UTXO sebagai input, dan UTXO-UTXO ini dihapus dari set. Setiap transaksi juga menciptakan UTXO baru sebagai output, dan UTXO-UTXO ini ditambahkan ke set. Setelah semua transaksi dalam block diproses, UTXO set mencerminkan state Bitcoin yang baru.

Urutan pemrosesan

Urutan pemrosesan dalam sebuah block penting. Transaksi pertama dalam setiap block selalu coinbase transaction: transaksi khusus yang tidak punya input dan hanya punya output. Ini adalah cara miner mendapatkan block reward plus semua fee transaksi dalam block tersebut. UTXO dari coinbase transaction ditambahkan ke UTXO set, tapi ada aturan khusus: UTXO coinbase tidak bisa dihabiskan selama 100 block ke depan. Ini disebut coinbase maturity. Transaksi-transaksi berikutnya diproses secara berurutan. Kalau transaksi B menggunakan output transaksi A dalam block yang sama, A harus muncul lebih dulu. Ini disebut topological ordering.

Rollback saat reorganisasi

Kadang terjadi reorganisasi chain: node menemukan chain yang lebih panjang yang berbeda dari chain yang sedang diikutinya. Saat ini terjadi, node harus melakukan rollback UTXO set ke state sebelumnya, lalu menerapkan block-block dari chain baru. Ini adalah operasi yang kompleks dan membutuhkan node untuk menyimpan informasi tentang perubahan UTXO set di setiap block agar bisa di-undo.

Efisiensi database

UTXO set disimpan dalam database key-value yang dioptimalkan untuk lookup cepat. Kuncinya adalah pasangan (txid, output index) yang secara unik mengidentifikasi setiap UTXO. Nilainya adalah data UTXO: jumlah satoshi, script yang harus dipenuhi untuk membelanjakannya, dan block height saat UTXO dibuat. Lookup ini harus selesai dalam milidetik karena node harus memverifikasi setiap input dari setiap transaksi yang masuk.

Proses pembaruan UTXO set adalah jantung dari operasi full node. Setiap node di seluruh dunia melakukan operasi yang sama persis saat memproses block yang sama, dan hasilnya selalu identik. Dari state yang sama, input yang sama selalu menghasilkan state yang sama.

Bab 10 · 10.3
Node memverifikasi transaksi hanya dengan data lokal
UTXO Set dan Verifikasi Transaksi

Salah satu fungsi paling kritis dari UTXO set adalah memungkinkan verifikasi transaksi yang cepat dan andal. Saat sebuah transaksi baru tiba di node, node tidak perlu membaca seluruh blockchain untuk memverifikasinya. Ia hanya perlu memeriksa UTXO set.

Apa yang diverifikasi?

Saat node menerima transaksi baru, ada beberapa hal yang diperiksa secara berurutan. Pertama, apakah setiap UTXO yang diklaim sebagai input benar-benar ada di UTXO set? Kalau tidak ada, transaksi ditolak karena mencoba membelanjakan sesuatu yang tidak ada. Kedua, apakah total nilai input lebih besar atau sama dengan total nilai output? Selisihnya adalah fee untuk miner. Ketiga, apakah script locking di setiap UTXO terpenuhi oleh script unlocking yang disediakan pengirim? Ini adalah verifikasi kriptografis bahwa pengirim memang berhak membelanjakan UTXO tersebut.

Kecepatan verifikasi

Karena UTXO set disimpan dalam database yang dioptimalkan untuk lookup cepat, verifikasi ini bisa selesai dalam hitungan milidetik bahkan untuk transaksi dengan banyak input. Node tidak perlu menelusuri seluruh sejarah blockchain, cukup query UTXO set dengan txid dan output index sebagai kunci.

Double spend detection

Double spend adalah upaya menggunakan UTXO yang sama lebih dari sekali. UTXO set membuat ini mustahil untuk transaksi yang sudah dikonfirmasi: begitu UTXO dikonsumsi dan dihapus dari set, ia tidak bisa digunakan lagi. Untuk transaksi unconfirmed di mempool, node memantau apakah ada dua transaksi yang mengklaim UTXO yang sama dan menolak yang datang belakangan.

Coinbase maturity

Ada satu pengecualian khusus dalam verifikasi: coinbase UTXO. UTXO yang berasal dari coinbase transaction tidak bisa dibelanjakan selama 100 block setelah block di mana coinbase itu ada. Ini disebut coinbase maturity. Tujuannya adalah memberi buffer waktu kalau terjadi reorganisasi chain yang menghapus block tersebut. Sebelum 100 block, coinbase UTXO memang ada di UTXO set tapi node menolak transaksi yang mencoba menggunakannya.

Desain UTXO set yang memungkinkan verifikasi cepat adalah salah satu alasan Bitcoin bisa beroperasi sebagai sistem desentralisasi tanpa server pusat. Setiap node bisa memverifikasi setiap transaksi secara mandiri, hanya dengan data lokal yang jauh lebih kecil dari blockchain penuh.

Bab 10 · 10.4
Setiap UTXO yang tidak perlu adalah beban kecil yang ditanggung seluruh jaringan
Ukuran dan Pertumbuhan UTXO Set

UTXO set bukan angka yang statis. Ia terus berubah seiring aktivitas jaringan. Memahami bagaimana ukuran UTXO set tumbuh dan bagaimana hal itu mempengaruhi node adalah bagian penting dari memahami ekonomi dan teknis Bitcoin jangka panjang.

Berapa besar UTXO set saat ini?

Per pertengahan 2026, UTXO set Bitcoin berisi lebih dari 170 juta UTXO dengan ukuran total sekitar 11 GB. Ini jauh lebih kecil dari blockchain penuh yang sudah lebih dari 700 GB. Tapi tidak berarti UTXO set tidak bisa menjadi masalah di masa depan.

Apa yang membuat UTXO set bertumbuh?

UTXO set bertumbuh saat lebih banyak UTXO dibuat daripada yang dikonsumsi. Ini terjadi dalam beberapa situasi: transaksi yang menghasilkan banyak output kecil tanpa batching yang baik, dust output yang tidak ekonomis untuk dihabiskan karena fee-nya lebih besar dari nilainya sendiri, dan lost coins yaitu UTXO yang private key-nya sudah hilang dan tidak akan pernah dikonsumsi tapi tetap ada di UTXO set selamanya.

UTXO bloat dan dust

Dust adalah UTXO dengan nilai satoshi yang sangat kecil, sering di bawah 546 satoshi untuk transaksi P2PKH. Output ini muncul di UTXO set tapi mungkin tidak pernah bisa dibelanjakan secara ekonomis. Setiap node harus menyimpan entry ini di database mereka. Seiring waktu, dust yang terakumulasi berkontribusi pada pertumbuhan UTXO set yang tidak produktif.

Mengapa ukuran UTXO set penting?

UTXO set harus bisa diakses dengan cepat, idealnya seluruhnya di RAM atau SSD yang cepat. Kalau UTXO set tumbuh terlalu besar, node dengan hardware terbatas akan kesulitan. Ini adalah salah satu alasan kenapa ada tekanan untuk menjaga UTXO set tetap ramping: semakin kecil UTXO set, semakin mudah menjalankan full node, dan semakin kuat desentralisasi jaringan.

UTXO consolidation

Saat fee mempool sedang rendah, pengguna bisa melakukan UTXO consolidation: mengirim banyak UTXO kecil ke dirinya sendiri dalam satu transaksi untuk menggabungkannya menjadi satu UTXO yang lebih besar. Ini mengurangi jumlah UTXO di set dan mempersiapkan diri untuk fee yang lebih efisien di masa depan saat mempool ramai.

UTXO set yang ramping adalah kepentingan bersama seluruh jaringan. Setiap UTXO yang tidak perlu dibuat adalah beban kecil yang harus ditanggung setiap full node di dunia. Praktik seperti batching transaksi dan UTXO consolidation bukan hanya efisiensi personal, tapi kontribusi nyata terhadap kesehatan jaringan.

Bab 10 · 10.5
Cara kamu mengelola UTXO bisa mengungkapkan lebih banyak dari yang kamu sadari
UTXO Set dan Privacy

UTXO set bukan hanya soal teknis dan efisiensi. Ada dimensi privasi yang penting untuk dipahami. Karena UTXO set adalah data publik yang bisa dianalisis oleh siapapun, cara kamu mengelola UTXO-mu bisa mengungkapkan lebih banyak informasi tentang keuanganmu daripada yang kamu sadari.

UTXO sebagai jejak

Setiap UTXO punya sejarah yang bisa dilacak. Dari mana asalnya, transaksi apa yang menciptakannya, dan siapa yang mungkin terlibat. Analisis blockchain bisa menghubungkan UTXO-UTXO yang berbeda ke pemilik yang sama dengan beberapa heuristik. Heuristik paling umum adalah common input ownership: kalau dua UTXO digunakan sebagai input dalam transaksi yang sama, analis blockchain berasumsi keduanya dimiliki oleh orang yang sama. Ini masuk akal karena untuk menggunakan UTXO, kamu harus membuktikan kepemilikan dengan menandatangani.

Change output dan privasi

Saat kamu mengirim Bitcoin dan ada kembalian, kembalian itu menciptakan UTXO baru di address-mu. Address mana yang merupakan kembalian dan mana yang merupakan pembayaran seringkali bisa ditebak oleh analis: biasanya kembalian adalah output dengan nilai yang tidak bulat, sementara pembayaran adalah angka yang lebih bulat.

Address reuse

Salah satu kesalahan privasi paling umum adalah menggunakan address yang sama berulang kali. Kalau kamu menerima Bitcoin di address yang sama dua kali, analis bisa menghubungkan kedua penerimaan itu dan mulai membangun gambaran tentang berapa total bitcoin yang kamu miliki. Wallet modern menggunakan HD wallet yang menghasilkan address baru untuk setiap transaksi, tapi tidak semua pengguna mengerti kenapa ini penting.

UTXO consolidation dan privasi

UTXO consolidation yang kita bahas di 10.4 sangat berguna secara teknis, tapi punya trade-off privasi. Saat kamu menggabungkan banyak UTXO dalam satu transaksi, kamu mengonfirmasi kepada analis bahwa semua UTXO tersebut milik orang yang sama. Kalau UTXO-UTXO itu berasal dari sumber yang berbeda, konsolidasi bisa mengungkapkan pola yang tidak ingin kamu ungkapkan.

CoinJoin sebagai solusi

CoinJoin adalah teknik di mana beberapa pengguna menggabungkan transaksi mereka menjadi satu transaksi bersama. Hasilnya adalah transaksi dengan banyak input dari banyak pengguna berbeda dan banyak output dengan nilai yang sama. Analis tidak bisa lagi menggunakan heuristik common input ownership karena input memang berasal dari banyak orang. Ini akan dibahas lebih dalam di Bab 12.

Privasi di Bitcoin bukan tentang menyembunyikan sesuatu yang ilegal. Ini tentang hak dasar untuk mengelola informasi keuanganmu sendiri. Sama seperti kamu tidak ingin semua orang tahu berapa saldo rekening bankmu, kamu juga berhak memilih siapa yang tahu berapa bitcoin yang kamu miliki dan dari mana asalnya.

Bab 10 · 10.6
Tantangan dan solusi untuk UTXO set jangka panjang
Masa Depan UTXO Set

UTXO set adalah komponen yang akan terus berevolusi seiring Bitcoin berkembang. Ada beberapa tantangan dan solusi yang sedang didiskusikan atau dikembangkan terkait bagaimana UTXO set dikelola di masa depan.

Pertumbuhan jangka panjang

Bayangkan sebuah buku catatan yang harus disalin ulang oleh setiap orang yang ingin memverifikasi transaksi Bitcoin. Semakin tebal buku itu, semakin lama proses penyalinannya dan semakin besar ruang yang dibutuhkan. Itulah analogi UTXO set. Kalau Bitcoin terus diadopsi secara masif, jumlah UTXO akan terus bertumbuh. UTXO set bisa mencapai puluhan gigabyte dalam beberapa dekade. Ini masih jauh lebih kecil dari blockchain penuh, tapi cukup untuk menjadi hambatan bagi node dengan hardware terbatas, terutama di negara berkembang di mana hardware mahal dan koneksi internet lambat.

Stateless validation dan UTXO commitments

Saat ini, untuk memverifikasi sebuah transaksi, node harus punya salinan lengkap UTXO set di komputernya sendiri. Ini seperti kasir yang harus hafal seluruh daftar barang di gudang sebelum bisa melayani pembeli. Ada ide yang sedang didiskusikan bernama stateless validation: daripada node yang menyimpan UTXO set, pengirim transaksilah yang membuktikan bahwa UTXO mereka memang ada dan valid. Bukti ini disebut UTXO commitment, semacam sertifikat kriptografis yang bisa diverifikasi tanpa perlu mengecek database lokal. Analoginya: daripada kasir hafal semua stok, pembeli membawa nota resmi dari gudang yang membuktikan barang itu ada. Kasir cukup verifikasi notanya. Ini masih dalam tahap penelitian dan membutuhkan perubahan signifikan pada protokol Bitcoin.

Assumevalid dan assumeutxo

Bitcoin sudah punya beberapa cara untuk mempercepat node baru bergabung ke jaringan tanpa harus memverifikasi ulang seluruh sejarah dari awal. Assumevalid adalah optimasi pertama: node baru bisa melewati verifikasi tanda tangan kriptografis untuk block-block yang sudah sangat lama. Alasannya masuk akal secara ekonomis: kalau jutaan node sudah sepakat bahwa block-block lama itu valid, hampir tidak mungkin semuanya salah. Assumeutxo adalah optimasi yang lebih baru dan lebih canggih: node baru bisa langsung menggunakan snapshot UTXO set yang sudah diverifikasi sebelumnya, dan mulai beroperasi normal dalam hitungan menit. Sementara itu, di latar belakang, node perlahan-lahan memverifikasi seluruh sejarah blockchain dari awal untuk memastikan snapshot itu memang benar.

Archival node vs pruned node

Tidak semua node menyimpan seluruh sejarah Bitcoin. Archival node menyimpan segalanya dari genesis block hingga hari ini dan inilah yang benar-benar menopang jaringan: tanpa cukup archival node, node baru tidak bisa bergabung karena tidak ada yang menyediakan data historis. Pruned node hanya menyimpan UTXO set dan beberapa ratus block terbaru. Ia bisa memverifikasi transaksi untuk dirinya sendiri, tapi tidak bisa membantu node lain yang baru sync. Pruned node berguna untuk keperluan verifikasi pribadi, bukan pengganti archival node.

UTXO set sebagai ukuran kesehatan

Ukuran dan komposisi UTXO set adalah salah satu indikator kesehatan jaringan yang bisa dipantau. UTXO set yang tumbuh terlalu cepat bisa mengindikasikan spam atau aktivitas yang tidak efisien. UTXO set yang stabil atau bahkan menyusut menunjukkan pengguna yang efisien dalam mengelola output mereka. Dust limit, batas minimum nilai UTXO yang diterima oleh node sebagai bagian dari mempool policy, adalah salah satu mekanisme untuk mencegah UTXO set dibanjiri output yang tidak berguna.

UTXO set adalah salah satu batasan sumber daya paling nyata dalam Bitcoin. Tidak seperti blockchain yang hanya perlu disimpan, UTXO set harus bisa diakses dan diquery dengan cepat. Ini menciptakan tekanan alami untuk tetap efisien, tekanan yang pada akhirnya menguntungkan seluruh pengguna jaringan.

Pruned node memverifikasi seluruh blockchain saat sync awal, tapi kemudian membuang data historis lama. Ia bisa memverifikasi transaksi untuk dirinya sendiri, tapi tidak bisa membantu node lain yang baru bergabung.
⚠️ Pruned node bukan pengganti archival node. Kalau semua orang hanya menjalankan pruned node, jaringan akan kesulitan menerima anggota baru karena tidak ada yang bisa menyediakan data historis. Pruned node berguna untuk verifikasi pribadi, bukan untuk menopang jaringan.

AssumeUTXO adalah optimasi cara node baru memulai, bukan kategori node yang berdiri sendiri. Node yang menggunakan AssumeUTXO bisa langsung beroperasi dalam menit menggunakan snapshot UTXO set, sambil memverifikasi sejarah penuh di background. Apakah ia menopang jaringan atau tidak tergantung apakah ia archival atau pruned.

Jaringan Bitcoin membutuhkan archival node yang cukup agar node baru bisa bergabung. Kalau semua orang hanya menjalankan pruned node, jaringan akan kesulitan menerima anggota baru. Menjalankan archival node adalah salah satu kontribusi paling nyata yang bisa dilakukan seseorang untuk Bitcoin.
